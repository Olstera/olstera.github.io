# Портфолио — Живописцева Оля

Локальный сайт: главная, каталог и шесть кейсов. На сайте работают статические HTML, CSS и JavaScript без сторонних библиотек. Сборщик использует только стандартную библиотеку Python 3.9+; отдельный генератор PDF имеет свои зависимости.

## Просмотр

Команды ниже выполняются из папки `site`:

```sh
python3 tools/build_projects.py --preview-blocks
python3 -m http.server 4173 --bind 127.0.0.1
```

Адрес: http://127.0.0.1:4173/. Если сервер уже запущен, достаточно пересобрать страницы и обновить браузер.

Формы редактируют JSON, а публикация пересобирает карточки и страницы автоматически. Пошаговая инструкция: [EDITOR_GUIDE.md](EDITOR_GUIDE.md).

## Редактирование проектов

В `content/projects.json` порядок массива задаёт порядок каталога и переходов «Следующий проект». Для каждого проекта:

- `slug` — уникальный адрес латиницей, например `o-sh`; создаёт `project-o-sh.html`.
- `name`, `description`, `type`, `role`, `intro` — название, направление, тип, роль и вводное описание.
- `published: true` — включить в публичную сборку. По умолчанию новый проект — черновик. Незаполненные черновики не мешают публикации других проектов.
- `featured: true` — показывать на главной. Порядок сохраняется; первая избранная карточка широкая.
- `cover` — обложка: локальный `src`, `alt`, необязательные целые `width` и `height`; `format` — `pinkly`, `square`, `portrait` или `landscape`. Вариант `pinkly` означает полное изображение с розовой подложкой. Каталог автоматически повторяет утверждённую композицию из шести карточек.
- `blocks` — содержательные блоки в нужном порядке; блоки можно повторять и переставлять.

| Тип блока | Содержимое |
| --- | --- |
| `text` | `title`, `text`; абзацы через два перевода строки |
| `image` | Заголовок слева, изображение справа |
| `image-wide` | Изображение на всю ширину под заголовком |
| `image-pair` | `title`, `images` ровно из двух изображений |
| `mobile-gallery` | `title`, `images` из двух и более изображений |

Поля изображения: `src`, обязательный `alt`, необязательные `caption`, `width`, `height`. Для `image` и `image-wide` также нужен `title`; `theme: "pinkly"` добавляет подложку. Изображения хранятся внутри `assets/`. Их высота определяется пропорциями файла; клик открывает полное полотно.

Вводная фраза `description` использует H4 (18px / mobile 16px). `intro` и все абзацы `text` используют `.case-body`: Inter 14px / 400 / line-height 1.55, normal tracking, второстепенный цвет на всех экранах.

Короткие предлоги и союзы автоматически связываются со следующим словом неразрывным пробелом: «в команде», «и визуал». Правило применяется к видимому тексту всех страниц, в том числе к новым описаниям. В JSON и шаблонах достаточно обычных пробелов. Разметка, ссылки и явные переводы строки сохраняются; общий обработчик находится в `tools/typography.py`. Список слов и правила приведены в UI-ките.

После изменения данных:

```sh
python3 tools/build_projects.py --preview-blocks
python3 tools/check_site.py
```

Библиотека примеров: http://127.0.0.1:4173/block-library.html. Она имеет `noindex` и не включена в меню. При удалении проекта старый HTML локального предпросмотра может остаться в `site`; его можно удалить. В новую папку `dist/` удалённые проекты не попадают.

## Проверка и подготовка к публикации

```sh
python3 -m unittest discover -s tools -p 'test_*.py' -v
python3 tools/check_site.py
python3 tools/build_release.py
```

Проверки охватывают синхронизацию карточек и кейсов, общие контакты, добавление и перестановку проектов, некорректный контент, пять типов блоков, ссылки и исключение технических файлов из публикации.

`build_release.py` заново собирает сайт из источников в `dist/`, копирует только используемые ресурсы и лицензию шрифта, проверяет ссылки и якоря. UI-кит, JSON, шаблоны, тесты, библиотека примеров и скриншоты туда не попадают. Скрытый `.portfolio-build` обозначает папку как результат сборщика; чужую папку без этого маркера команда не перезаписывает. Повторная сборка удаляет устаревшие страницы и ресурсы только внутри собственного `dist/`.

Это подготовка файлов, **не публикация**. Для финального просмотра можно запустить отдельный локальный сервер: `python3 -m http.server 4174 --bind 127.0.0.1 --directory dist`.

## Публикация и кабинет

Репозиторий: https://github.com/Olstera/olstera.github.io. Целевой адрес: https://olstera.github.io/. Свадебный сайт в отдельном репозитории не затрагивается.

- `.github/workflows/check.yml`: проверка при сохранении файлов.
- `preview.yml`: ручная сборка архива, включая готовые черновики; публикации нет.
- `publish.yml`: ручная проверка, сборка и выкладка в GitHub Pages. В настройках Pages нужно выбрать GitHub Actions.
- `.pages.yml`: редактор проектов, пяти видов блоков, обложек и контактов. Авторизация через GitHub в https://app.pagescms.org/.
- Сохранение не запускает выкладку. Для неё предусмотрено отдельное действие «Опубликовать сайт».
- Генерируются canonical/Open Graph, robots.txt и sitemap.xml. Публичный адрес задаётся один раз в `tools/build_projects.py` (`PUBLIC_URL`). При смене домена обновить его.
- UI-кит и исходные референсы остаются локально в родительской папке; не входят в этот репозиторий.

GitHub Actions собирает сайт непосредственно из данных: готовые HTML можно не хранить в Git. Ошибка проверки не заменяет текущий сайт. Репозиторий публичный: черновики исключаются из сайта, но исходные файлы остаются доступны через GitHub. `tools/fixtures/` изолирует регрессионные проверки от редактируемых кейсов.
