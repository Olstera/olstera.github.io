# Как обновлять портфолио

Сайт: https://olstera.github.io/  
Кабинет: https://app.pagescms.org/  
Репозиторий: https://github.com/Olstera/olstera.github.io

09.10.2026 сайт опубликован, а приложение Pages CMS установлено только для `Olstera/olstera.github.io`. Свадебный репозиторий не подключён. Владелец сайта подтвердил доступ к разделам «Проекты» и «Имя и контакты» и сохранил тестовый проект; запись проверена в GitHub, тестовый элемент удалён. Встроенный браузер Codex выдаёт ошибку соединения с сервисом, поэтому загрузка изображения и запуск действий именно из кабинета пока не проверены. Публикация через GitHub Actions успешно проверена отдельно.

## Вход

Войдите в Pages CMS через свой GitHub, выберите `Olstera / olstera.github.io` и ветку `main`. При установке GitHub App выбирайте только репозиторий портфолио. Кабинет защищён входом в GitHub; знание его адреса само по себе не даёт права редактирования.

Подписка ChatGPT для работы с кабинетом и сайтом не нужна. Все тексты, изображения и история изменений хранятся в вашем репозитории. По условиям на момент настройки онлайн-версия Pages CMS бесплатна: https://pagescms.org/.

## Добавить кейс

1. Откройте «Проекты» и добавьте элемент списка.
2. Заполните название и уникальный адрес латиницей: например `new-project`. Остальные поля можно заполнить позже, пока проект остаётся черновиком.
3. Заполните направление, тег, свою роль и вводное описание. Направление — крупнее, описание и текстовые блоки — обычный наборный текст.
4. В обложке загрузите изображение, опишите его в поле «Что изображено» и выберите формат. Описание изображения обязательно для публикации: оно помогает людям, использующим экранный диктор.
5. Добавьте блоки в нужном порядке. Заголовки и описания перед публикацией не должны быть пустыми. Абзацы текста разделяйте пустой строкой. Не вставляйте HTML.
6. При необходимости включите «Показывать на главной». Порядок списка определяет порядок каталога и избранных работ.
7. Нажмите Save / «Сохранить». Сайт пока не изменяется.

Новые проекты по умолчанию исключены из публикации. Можно сохранить незаполненный черновик, не мешая обновлению других проектов. Для публикации должен остаться хотя бы один готовый проект.

## Какие бывают блоки

| Блок | Что заполнить |
| --- | --- |
| Текст | Заголовок слева и обычные абзацы справа |
| Изображение справа | Заголовок и один файл; длинное полотно сохраняет естественную высоту |
| Изображение на всю ширину | Заголовок и один файл на всю контентную ширину |
| Два изображения рядом | Заголовок и ровно два изображения; на телефоне идут друг за другом |
| Мобильные экраны | Заголовок и не менее двух изображений; на телефоне листаются горизонтально |

Блоки можно повторять, удалять и переставлять. У изображений есть необязательная подпись. На сайте каждое открывается в поп-апе, где доступно полное полотно и масштаб 100%.

JPG, PNG и WebP поддерживаются. Высоту задаёт сам файл, вводить её вручную не нужно. Для длинных экранов разумно экспортировать ширину около 1400–1800px; для прозрачности — PNG/WebP. Лучше загружать подготовленные файлы до нескольких мегабайт. Автоматическое сжатие и обработка фотографий пока не включены. Имя файла при загрузке меняется автоматически во избежание совпадений; исходник на компьютере не изменяется.

## Предпросмотр

После сохранения выберите «Собрать предпросмотр». Эта команда включает также черновики, поэтому для неё нужно заполнить их так же, как готовые проекты. Незаконченный черновик вызовет ошибку предпросмотра, но не повлияет на действующий сайт.

Откройте запуск «Предпросмотр сайта» по ссылке из действия или в GitHub → Actions. После успешной сборки скачайте архив `portfolio-preview` в разделе Artifacts, распакуйте его целиком и откройте `index.html`. HTML и соседние папки должны остаться рядом. Архив хранится 7 дней; при необходимости соберите снова.

Это просмотр скачанной копии, а не встроенный визуальный редактор. В архиве есть черновики: не используйте его для ручной публикации.

## Публикация

1. Включите «Включить в публикацию» у готовых кейсов и сохраните.
2. Выберите «Опубликовать сайт» и подтвердите обновление сохранённых данных.
3. Дождитесь успешного завершения действия. Если проверка находит ошибку, текущий сайт продолжает работать в прежнем виде. Откройте ошибочный шаг, исправьте указанное поле и повторите публикацию.
4. Откройте сайт и проверьте главную, каталог и новый кейс.

Для снятия работы с сайта выключите её переключатель публикации, сохраните и опубликуйте сайт снова. Адрес уже опубликованного кейса лучше не менять: внешние ссылки ведут на прежний адрес.

## Контакты и остальные тексты

В разделе «Имя и контакты» меняются имя, фамилия, год, почта, Telegram и Instagram. Ссылки вводятся полностью, начиная с `https://`. Они обновляются во всех меню и футерах после публикации. Подпись «совместно с Codex» общая для всех страниц.

Тексты обложки и этапов работы пока находятся в шаблоне главной страницы; в формах кабинета редактируются кейсы и контакты. Типографика, цвета и сетка зафиксированы в UI-ките и не меняются от редактирования контента.

## Восстановление и резервная копия

Сохранения образуют историю GitHub. Ошибочный текст проще исправить повторно в кабинете и снова опубликовать. Полную резервную копию текущего состояния можно скачать на странице репозитория: Code → Download ZIP. Храните исходные изображения также у себя. Перед проверкой кабинета сохранён отдельный локальный архив `Моё портфолио/backups/portfolio-before-cms-2026-10-09.zip`: исходники сайта, UI-кит и правила проекта. После новых публикаций обновляйте резервную копию отдельно от GitHub.

Для возврата к старой версии откройте историю нужного файла (`content/projects.json` или `content/site.json`), найдите нужное сохранение и восстановите его содержимое новым коммитом. Для полной истории можно клонировать репозиторий через GitHub Desktop. Архив ZIP содержит только текущее состояние.

Репозиторий публичный: черновики не видны на сайте, но их тексты и изображения доступны через GitHub. Не загружайте конфиденциальные материалы. Удаление файла не удаляет его из истории.

Если Pages CMS временно недоступен, сайт продолжает работать. Запасной способ редактирования — изменить JSON через GitHub и запустить Actions → «Опубликовать сайт» → Run workflow. Это не требует Codex, но требует аккуратного редактирования JSON.

## Первоначальная настройка GitHub Pages

В Settings → Pages уже выбран Source → GitHub Actions. Публикация выполняется только ручным workflow, без персонального токена: используется временное разрешение GitHub Actions. Установка Pages CMS и запись тестового проекта подтверждены в GitHub. Проверка загрузки файла и запуска действий из самого кабинета остаётся отдельным шагом; до неё не следует считать весь сценарий редактирования проверенным.
